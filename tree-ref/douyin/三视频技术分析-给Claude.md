# 三个抖音参考视频技术分析（给 Claude）

> 来源：用户 2026-10-18 在 AI_Corp #18 留言贴的 3 个抖音视频（录屏已存 `tree-ref/douyin/`）。
> 目标：搞清楚每个视频"怎么做出来的"，评估我们的旅行树（2D 网页 Canvas）能不能借鉴/复用。

## 视频1：Blender 几何节点植物生长系统（序号1）

- **原视频**：抖音 @Lan_er2《在Blender里制作了一整个植物生长/散布生长系统》，2026-06-13
- **怎么做出来的**：Blender 5.0.0 的**几何节点（Geometry Nodes）**——可视化节点编程。作者搭了一套 100+ 节点的植物生长节点组，参数化控制生长、分支、散布。Blender 免费开源，难的是作者那套节点系统本身（评论区都喊大佬）。
- **能不能搞**：**思路可借鉴，技术无法复用**。这是 3D 建模工具链，我们的旅行树是 2D 网页 Canvas。但"用参数驱动生长过程"的思路是对的——我们的树也应该由参数控制生长，而不是硬编码画死。

## 视频2：树鸭儿 V0.1（序号2）

- **原视频**：抖音 @弄弄鸭儿《开源树鸭儿V0.1！快速建模你的植物》，2026-10-03
- **怎么做出来的**：作者自研的程序化植物建模软件"树鸭儿"，跑在 **UE5** 里。**注意：结尾没有 GitHub 仓库地址**，作者说的是"软件在评论区网盘"——走网盘分发，不是 GitHub 开源项目。
- **能不能搞**：**技术栈完全不同，无法复用**。UE5/3D 游戏引擎 vs 我们的 2D 网页。可借鉴的是交互思路：调参数→实时看到植物变化，这种"参数化实时预览"体验好。

## 视频3：EZ-Tree（序号3）⭐ 最相关

- **原视频**：抖音 @答案《不会建模？这个开源项目帮你 30 秒生成 3D 树木！》，2026-06-12
- **怎么做出来的**：**EZ-Tree**，Dan Greenheck 写的浏览器端程序化树生成器。
  - 技术栈：JavaScript + **three.js**（WebGL），纯浏览器运行
  - 开源协议：**MIT**（可自由参考/改编）
  - 仓库：https://github.com/dgreenheck/ez-tree
  - 在线演示：https://eztree.dev
  - 原理：递归分支生成 + 种子随机数（seeded RNG），15 种树种预设（松/橡/灌木丛等），50+ 可调参数（分支层级、长度、叶密度、树皮颜色等），可导出 GLB/PNG
- **能不能搞**：**最接近、可借鉴**。虽然它是 3D（three.js）而我们是 2D Canvas，但核心的**分支生成算法**（递归 + 参数化 + 种子随机）可以直接 2D 化：
  1. 它的 `TreeOptions` 参数体系（trunk.length、branch.levels、seed 等）正是我们需要的"树按自己规律长"的参数化方案
  2. 递归分支 + 种子随机的思路，保证"只往上加、不重排"（seed 固定，已生成的部分不变）
  3. MIT 协议，代码可直接参考

---

## 给旅行树的建议（供 Claude 参考）

1. **采用 EZ-Tree 式的参数化递归分支算法**，2D 化：主干→分支→小枝，递归深度/长度/角度由参数 + 种子随机数决定
2. **生长动画**：从 seed 开始随"地方数量"逐步展开分支（参考视频1的生长感），已挂果子的分支 seed 不变→不重排
3. **果子挂载**：每个果子绑定到一个分支末端节点（branch tip），新地方→新分支→新果子，老的不动
4. 不需要 3D，不需要把 EZ-Tree 整个搬过来——**只借它的算法骨架**，渲染仍用我们现在的 2D Canvas + 淡蓝配色 + 光晕
